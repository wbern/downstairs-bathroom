## What was built

The IFC arrived by email on 2026-07-27 (Martin Häger, Studio Streck) after
William asked for the CAD file to "play with materials and visualisation". It's
the same drawing as the existing PDF hero, but with real 3D geometry — 45
objects, 13 684 triangles, in a 2.28 × 1.13 m room with a 2.13 m ceiling.

`tools/ifc_to_json.py` is a from-scratch STEP parser (no dependencies — nothing
like IfcOpenShell is installed). It resolves placement chains, mapped items and
faceted breps, triangulates with ear-clipping, and reads `IFCSTYLEDITEM` surface
styles so every object is split into one mesh per material. That last part is
what makes the palettes trustworthy: the colours are anchored to what the
drawing specifies, not guessed per object. Run it with no arguments beyond
in/out paths; it prints the style table and per-object assignment.

The viewer covers: three cameras (cutaway isometric, near-orthographic plan,
eye-level walk-in), four palettes, independent wall-height and wall-transparency
sliders, automatic fading of whichever walls sit between camera and room, 13
toggleable element groups, and tap/hover identification with dimensions.

## Open threads

**Needs a decision from William / Ruiying**

1. **Black fittings are a deviation.** The IFC specifies `_METALL_ROSTFRITT`
   (stainless) for the shower, mixer, towel warmer and handles. William asked for
   black, so *Svart* overrides it — but that is not what Studio Streck drew.
   *Matt-silver* shows the stainless version, *Ritning* shows the drawing exactly.
   Worth confirming with Martin, and it should agree with whatever the `PRODUCTS`
   data in `index.html` actually specifies.
2. **Microcement colour.** The drawing says neutral grey `#b1b1b1`; the March
   email brief said beige. *Svart*/*Matt-silver* use a warmed `#bcb09c`. Nobody
   has confirmed a real product colour — see the microcement supplier thread in
   `INVENTORY.md`.

**Technical, safe to pick up**

3. **Joinery classification is inferred.** Vanity vs wall cabinet is split by
   height because the IFC calls both `" Tom NNN"`. It's correct for this model
   but would silently break on a revised export. If Martin sends a new IFC,
   re-check the converter's printed assignment before trusting the viewer.
4. **The IFC header leaks the architect's local path**
   (`/Users/martin/…/Dropbox/…`). It's in a public repo. Low risk, and I left the
   file byte-identical rather than quietly editing a document from a third party —
   but flag it to William if he cares.
5. **The DWG is unused.** It's the 2D AutoCAD version; the IFC supersedes it for
   3D. Kept only for completeness.
6. **No first-person movement.** The walk-in view is still an orbit camera with a
   movable pivot, not WASD/joystick navigation. Fine for 2.58 m², but it was
   raised and consciously deferred.
7. **The mirror doesn't reflect.** It's a metallic material with an environment
   map, not a real reflection. A `CubeCamera` would look considerably better in
   the walk-in view.
8. **Three.js is vendored unminified** (1.3 MB, ~300 KB gzipped). Fine over
   Pages, but a minified build or a CDN would cut mobile load time.
